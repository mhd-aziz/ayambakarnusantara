# REVIEW-2026-08-25 — QA Menyeluruh (Read-Only)

Audit keamanan & kualitas **mode read-only** (tidak ada kode diubah) pada
monorepo Ayam Bakar Nusantara, melanjutkan `REVIEW-2026-08-23.md` dan
`REVIEW-2026-08-23-part2.md`. Semua temuan diverifikasi langsung dari kode
(dengan kutipan baris), bukan asumsi. Dokumen ini ditulis sebagai acuan kerja
agen AI / pengembang berikutnya.

Scope: docs (13 file) · backend (12 controller, middleware, utils, SQL/RPC,
migration) · frontend (pages, components, context, services) — ±17.000 baris.

---

## 0. Verdict Umum

Arsitektur **sehat untuk skala MVP**: RPC atomik di Postgres (create/cancel
order, rating), RLS aktif, ownership check konsisten di semua controller,
nol XSS, state machine order sesuai BUSINESS-FLOW.md, dan dokumentasi sangat
rapi. Namun audit menemukan:

1. Beberapa klaim "Selesai" di ROADMAP **tidak sepenuhnya benar** (paling
   serius: #10 magic-bytes — validator di-import tapi tidak pernah dipanggil).
2. Celah keamanan yang masih terbuka: logout tanpa revoke sesi, rate limiter
   hanya ada di satu endpoint.
3. Inkonsistensi docs vs kode pada 4 titik.

---

## 1. Temuan — HIGH

### 🔴 H1 — Logout & reset password tidak me-revoke sesi Supabase

- **Lokasi**: `backend/src/controllers/authController.js:180-188` (logout),
  `:356` (resetPassword), cookie refresh 7 hari di `:20`.
- **Bukti**:
  ```js
  exports.logout = (req, res) => {
    try {
      clearSessionCookies(res);
      return handleSuccess(res, 200, "Logout berhasil.");
  ```
  Grep `signOut|revoke` di seluruh `src/` = **tidak ada hasil**.
- **Dampak**: refresh token yang dicuri tetap valid hingga 7 hari meski user
  sudah logout atau sudah ganti password.
- **Saran fix**: panggil `supabaseAdmin.auth.admin.signOut(refreshToken)` /
  revoke by user saat logout & setelah reset password berhasil.

### 🔴 H2 — Validasi magic bytes HANYA aktif di chat; ROADMAP #10 mengklaim salah

- **Lokasi**: `backend/src/utils/storageHelper.js:15-21`; upload tanpa
  validasi di `productController.js:140-149` & `:422-437`,
  `profileController.js:93-107`, `shopController.js:101-110` & `:192-207`.
- **Bukti**: `storageHelper.uploadImage()` meng-import
  `validateImageMagicBytes` (baris 3) tapi **tidak pernah memanggilnya**:
  ```js
  async function uploadImage(bucket, filePath, buffer, contentType) {
    const { error } = await supabaseAdmin.storage
      .from(bucket)
      .upload(filePath, buffer, { contentType, upsert: true });
  ```
  Satu-satunya pemanggil nyata: `chatController.sendMessage`
  (`chatController.js:279`).
- **Dampak**: MIME check multer dikontrol klien; file arbitrer (HTML/SVG/
  polyglot) bisa masuk bucket **publik** dengan ekstensi dari
  `originalname.split(".").pop()`. Klaim ROADMAP #10 "Diterapkan di
  chatController.sendMessage (+ storageHelper.uploadImage)" = **fix palsu**.
- **Saran fix**: panggil `validateImageMagicBytes(buffer)` di dalam
  `uploadImage()`/`uploadPrivateImage()` → menutup SEMUA titik upload sekaligus;
  perbaiki teks ROADMAP #10.

### 🔴 H3 — Tidak ada rate limiter di endpoint auth & endpoint publik berat

- **Lokasi**: grep `createRateLimiter` hanya terpakai di
  `backend/src/routes/feedbackRoutes.js:4-7`.
- **Tanpa proteksi**: `/auth/login` (brute-force password),
  `/auth/register`, `/auth/forgot-password` (email bombing via Resend → biaya),
  `POST /chatbot/ask` (proxy LLM berbiaya + timeout 60s),
  `GET /product|rating|shop` (search ilike).
- **Catatan**: temuan ini tercatat juga di `REVIEW-2026-08-17.md` namun belum
  pernah dituntaskan; ROADMAP tidak memuatnya lagi.
- **Saran fix**: pasang limiter ketat (mis. 5/15 menit) di login/register/
  forgot-password, limiter cost-based di `/chatbot/ask`.

## 5. Area AMAN (terverifikasi eksplisit)

1. **Role/bypass role** — `isSeller` (`authMiddleware.js:155-170`) selalu query kolom `role` dari DB, bukan klaim JWT; controller seller double-check lagi. Tidak ada kode percaya `req.user.role` JWT.
2. **IDOR** — semua operasi profil/toko/order/rating/notifikasi/chat di-scope ke `req.user.uid` dari token terverifikasi Supabase; chat cek partisipan di semua endpoint.
3. **Stok & harga** — RPC atomik `create_order`/`cancel_order` dengan `FOR UPDATE` + guarded decrement; harga snapshot dari DB saat masuk cart; nilai client tidak dipercaya.
4. **Rating spam** — unique `(user_id, product_id, order_id)` + ownership check di dalam SQL RPC (`rating-functions.sql:124,171`).
5. **State machine order** — transisi seller whitelist persis sesuai BUSINESS-FLOW.md; cancel hanya status awal dengan restore stok.
6. **XSS** — nol `dangerouslySetInnerHTML` / `href="javascript:"`; semua konten user dirender teks polos; link gambar chat dibatasi regex https+ekstensi.
7. **Enumerasi forgot-password** — pesan respons identik + jeda 400ms anti-timing (`authController.js:223-229,293-297`).
8. **Cookie flags** — httpOnly, secure di prod, maxAge eksplisit (24h/7h); single-flight refresh mencegah race rotasi token per-proses.
9. **CORS** — whitelist `CORS_ALLOWED_ORIGINS` + credentials; origin asing ditolak.
10. **Cleanup hapus akun** — tuntas: foto profil, banner, gambar produk, foto chat (bucket publik), bukti bayar privat (`authController.js:393-496`).
11. **Path traversal storage** — `extractPathFromPublicUrl` menolak `..`, skema absolut, leading `/` (`storageHelper.js:62-76`).
12. **Secret di log** — Midtrans key & OMNIROUTE_API_KEY tidak ter-log (fix 23 Agu terverifikasi).
13. **FE guard seller server-side** — SellerPage verifikasi ulang via `GET /profile`, tidak percaya localStorage.

## 6. Rekomendasi Urutan Kerja (untuk agent/dev berikutnya)

1. **H1 + H3**: revoke sesi di logout/reset-password; rate limiter login/register/forgot-password + `/chatbot/ask`.
2. **H2**: pindahkan `validateImageMagicBytes(buffer)` ke dalam `uploadImage()`/`uploadPrivateImage()` (satu titik, menutup semua upload) → update klaim ROADMAP #10.
3. **M1 + M4**: netralkan default branch `handleError`; hapus `email` dari response publik detail toko.
4. **M3 + M5**: guard order aktif sebelum `deleteShop`; sinkronkan displayName → shops.
5. **M6–M10**: urutan operasi upload/validasi, semantik rekomendasi (`average_rating`), clamp limit, hardening chatbot, RPC unread_counts.
6. **M11–M13 (FE)**: pisahkan error aksi vs load; arahkan HomePage ke `GET /product/recommendations`; verifikasi sesi saat boot alih-alih percaya localStorage.
7. **L1–L13**: batch kecil, aman dikerjakan paralel.
8. Setiap fix wajib: tambah test regression di `tests/`, jalankan suite backend + frontend, perbarui ROADMAP & Log perubahan (pola yang sudah terbukti di review-review sebelumnya).

## 7. Kesimpulan

Tidak ditemukan temuan CRITICAL (tidak ada auth bypass, IDOR, SQL injection,
atau XSS). Proyek dalam kondisi **layak MVP**, dengan 3 HIGH yang sebaiknya
ditangani sebelum exposure publik yang lebih luas: revoke sesi saat logout,
magic-bytes validation yang benar-benar aktif di semua upload, dan rate
limiting endpoint auth/chatbot. Klaim penyelesaian di ROADMAP perlu
diaudit silang dengan kode — dua kasus di dokumen ini menunjukkan klaim
"Selesai" yang tidak akurat (#10, dan #rate-limit yang hilang dari daftar).

## Addendum — Validasi ulang agen lanjutan (25 Agu 2026)

Dokumen ini divalidasi ulang oleh agen berikutnya (read-only) terhadap kode
nyata. Hasilnya: **semua temuan terkonfirmasi** — HIGH 3/3, MEDIUM 13/13,
LOW 13/13, Seksi 4 (docs vs kode) 5/5. Verdict "nol CRITICAL" benar. Dua
koreksi dibuat pada klaim dokumen asli:

1. **M3 (dampak dilebih-lebihkan):** kalimat "produk hilang dari order
   (cascade), pembeli tak bisa melanjutkan transaksi" **tidak akurat**.
   `orders.items` adalah **JSONB snapshot** (`schema.sql:86` —
   `[{productId, shopId, name, price, quantity}]`), bukan FK ke `products` yang
   di-cascade. Detail order pembeli dibaca langsung dari snapshot
   (`orderController.js:16,190-191,435-442`). Dampak nyata yang lebih tepat:
   order aktif jadi **tanpa penanggung jawab** (toko + produk terhapus, RLS
   seller yang join `shops` ikut kosong), status bisa terkatung-katung — produk
   di order **tetap utuh**.
2. **L6 (sitasi keliru):** referensi "`app.js:14`" salah — baris itu isi
   konfigurasi dotenv. Konfigurasi cookie `sameSite: "None"` yang benar ada di
   **`authController.js:14`**. Substansi temuan (CSRF bertumpu CORS) tetap
   valid.

### Fix yang diterapkan setelah validasi (25 Agu 2026)
- **H1** — `logout` kini memanggil `supabaseAdmin.auth.admin.signOut(refreshToken)`
  (revoke server-side) sebelum `clearSessionCookies` (`authController.js:180-190`).
- **H2** — magic-bytes kini aktif di SEMUA upload: `assertValidImageBuffer`
  (baru, di `utils/imageValidation.js`) dipanggil di
  `storageHelper.uploadImage` & `uploadPrivateImage` — bukan hanya chat.
- **H3** — rate limiter dipasang di `/auth/register`, `/auth/login`,
  `/auth/forgot-password` (`authRoutes.js`) dan `/chatbot/ask` (`chatbotRoutes.js`).
- **M4** — `email` owner dihapus dari respons publik `GET /shop/:shopId/detail`
  (`shopController.js:624-637`).
- Regression test baru: `tests/qa-audit-fix-2026-08-25.test.js` (11 PASS).

### Catatan tambahan dari validasi (bukan temuan baru, pemahaman perilaku)
- Rate limiter (`rateLimiter.js`) memakai **satu `Map` bucket module-level** yang
  dimiliki bersama oleh semua `createRateLimiter()` — login, register,
  forgot-password, feedback, dan chatbot berbagi counter per IP. Ini membatasi
  akurasi limiter per-endpoint dan memperkuat relevansi L5 (tanpa
  `app.set("trust proxy")`). Tidak mengubah urgensi H3, tapi worth dicatat.
- Pseudocode `createRateLimiter` hanya per-proses (L7); untuk multi-instance
  deploy tetap ada celah rotasi token.
